1. EXECUTIVE SUMMARY
================================================================================

We operate "Rubber Band Bot v8" — a calendar-aware, regime-switching, multi-
strategy US equity bot on Alpaca (LIVE, not paper). Starting equity ~$500.
Universe: S&P 500 + MidCap 400 (~900 stocks). Bot scans for mean-reversion /
panic-recovery entry signals, holds 1–3 days, exits on midline (price > 20d MA),
stop-loss (-0.5%), or max-hold (3 days).

LIVE RESULTS (Apr–Jun 2026): Roughly flat to slightly down (~$500 → ~$482).
Win rate on closed trades ~35%. Profit factor < 1. Primary drag: STOP LOSSES
fill far worse than modeled (-0.5% trigger → mean ~-1.7% realized loss).

SIMULATION RESULTS: Headline backtests show spectacular returns (+266% 3yr,
+30,110% 20yr) under ideal gap model. With EMPIRICAL stop slippage from live
logs, same sims collapse (+27% 3yr, +895% 20yr). Simulation overstated edge
because it assumed stops near -0.5%; live stops overshoot by ~1.2 percentage
points on average.

MAJOR JUNE WORK: (a) hardened CI/log pipeline after bot stopped logging Jun 11–13,
(b) investigated stop overshoots and deployed market_urgent_full stop sells,
(c) ran extensive validation sims (3yr/7yr/20yr), (d) validated overnight PDT
schedule (buy afternoon, sell morning), (e) switched live bot to EVENING_ONLY
entries, (f) added daily slippage monitoring and daily log reconciliation.

BOTTOM LINE FOR REVIEWER: Strategy logic may be sound in sim, but LIVE edge is
being eaten by (1) stop execution slippage, (2) PDT deferrals when schedule was
wrong (morning buys + same-day stops blocked), (3) fractional positions without
broker GTC stops relying on software exits. We are stabilizing execution before
considering strategy expansion (adding new strategies from sim bake-offs).

9. THE CORE PROBLEM: STOP-LOSS EXECUTION VS SIMULATION
================================================================================

9.1 WHAT SIM ASSUMES
  validation_sim.py uses EXIT_STOP_LOSS = -0.5% with gap model or empirical
  distribution from live stops (Test 33). Ideal gap model: stop fills at
  trigger. Empirical: samples actual stop P&L from transactions.csv.

9.2 WHAT LIVE DOES
  Trigger: position P&L <= -0.5% → software exit or GTC stop-market.
  Actual mean stop P&L (245+ samples): -1.68% (overshoot -1.18pp vs -0.5%).

  Why overshoot happens:
  (a) Overnight gap through stop level (open below stop)
  (b) Limit-first sell logic missing fast move (limit_fill_position_check)
  (c) PDT deferral → sell next day at worse price
  (d) Fractional shares: no GTC; relies on cron catching breach
  (e) 15-min cron granularity — price can move past stop between checks

9.3 SIM IMPACT (from extensive_sim_analysis_synthesis.md)
  3yr:  +266% baseline → +27% with empirical stops (-238pp)
  20yr: +30,110% baseline → +895% with empirical stops

9.4 FIXES ATTEMPTED
  - stop-MARKET instead of stop-LIMIT on GTC orders
  - place_all_stops() after every buy and at start of exits
  - cancel_stop_orders() before software sells (avoid double sell)
  - do_sell(urgency="urgent") → market_urgent_full for stop breaches
  - Same-day stop exits allowed even under STRICT_SAME_DAY_EXIT (stop breaches)
  - daily_slippage_watch.md monitors overshoot daily

9.5 NON-STOP EXECUTION (good)
  SELL slippage mean ~-0.05% (execution_audit). BUY slippage ~0%.
  Regular midline/max-hold sells are NOT the problem.

10. PDT (PATTERN DAY TRADER) CONSTRAINTS
================================================================================

Account < $25k → PDT rules apply if same-day buy+sell counts as day trade.

Live setting: STRICT_SAME_DAY_EXIT = True (because PAPER_TRADING = False)
  - Same-day midline and max-hold exits DEFERRED if position entered today.
  - Stop breaches CAN exit same day (implemented after Jun 10 incident).

Old schedule problem: morning_scan bought at open → stop hit same afternoon →
couldn't sell → overnight loss. FIXED by EVENING_ONLY_ENTRIES.

Sim-validated alternative: overnight_pdt schedule
  - Afternoon entry only, morning exit only, 0 day trades.
  - 8yr sim on $500: overnight_pdt +158% vs strict_pdt +103%.
  - See logs/analysis/pdt_schedule_sim_report.md

pdt.json + pdt_n() tracks today's entries for dynamic entry cap.

17. GLOSSARY
================================================================================

Midline exit     — Sell when price > 20-day moving average
Overshoot        — How much worse than -0.5% stop trigger the actual loss is
PDT              — Pattern Day Trader rule (<$25k, limited day trades)
GTC stop-market  — Broker-held stop that becomes market order when triggered
Fractional       — Sub-share dollar-based orders (~$15 positions common)
Plan cache       — JSON file from prep run to speed up execute run
ext_exits        — Post-4pm extended hours exit mode (limit orders)
market_urgent_full — Immediate market sell for stop breaches
strict_pdt       — Sim mode: no same-day sells (old live behavior)
overnight_pdt    — Sim mode: afternoon buy, morning sell only
Empirical stops  — Sim using actual stop P&L distribution from live logs
Gap model        — Sim assuming stop fills at trigger with gap adjustment
