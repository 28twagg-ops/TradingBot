--- PHASE 1: STRATEGY DESIGN & BACKTESTING ---

Started by testing 6 mean-reversion entry strategies across
S&P 500 stocks over 2/3/5/7 year windows. Strategy "bakeoff"
compared all combinations. Results that survived:

  RubberBand  : RSI < 35 + price near lower Bollinger Band
  52wkLow     : price near 52-week low
  MomReversal : sharp recent decline, betting on bounce
  GapDown     : stock gapped down significantly (panic selling)
  VolumeSpike : unusual volume suggesting institutional buying
  Pullback50  : uptrending stock pulled back to 50-day MA

Strategies removed: GoldenCross (negative Sharpe, lost money)

Exit rules tested and settled on:
  - Midline exit: price crosses back above 20-day Bollinger midband
  - Stop loss: -2% (checked every 15 min by software)
  - Max hold: 5 days (forces exit regardless of P&L)

Sizing:
  - Seasonal match position (primary strategy for month): ~20% of equity
  - Off-schedule position: ~12% of equity
  - Cash reserve: 15% always kept aside
  - No hard cap on open positions -- cash is the real constraint

Calendar (which 2 strategies get larger sizing each month):
  Jan: MomReversal + 52wkLow    Jul: 52wkLow + Pullback50
  Feb: 52wkLow + VolumeSpike    Aug: RubberBand + 52wkLow
  Mar: 52wkLow + MomReversal    Sep: GapDown + VolumeSpike
  Apr: RubberBand + Pullback50  Oct: RubberBand + GapDown
  May: RubberBand + 52wkLow     Nov: RubberBand + MomReversal
  Jun: 52wkLow + VolumeSpike    Dec: MomReversal + VolumeSpike

Regime filter (SPY vs its 200-day MA):
  Bull (ratio >= 1.0)        : all strategies active
  Correction (0.93-1.0)      : all strategies active
  Bear (ratio < 0.93)        : only 52wkLow + MomReversal

--- PHASE 2: SIMULATOR VALIDATION ---

7-year backtest on ~900 S&P 500 stocks showed:
  - With naive -3% stop cap (hides gap risk): $500 -> ~$10,000
  - With realistic 2x slippage floor (-6% max): $500 -> ~$3,000-5,000
  - Uncapped (includes data artifacts): ~$500

Walk-forward test (60% in-sample, 40% out-of-sample):
  In-sample win rate: 51%
  Out-of-sample win rate: 58.4%
  OOS outperformed IS -- strategy is NOT overfit, edge is real.

PDT rule: 0 same-day round trips in 7yr sim. Not a constraint.

Key risk identified: gap-down events can bypass stop orders.
2020 COVID: equity dropped from $449 to $288 in one month in sim.
Real bracket orders would have limited this but not eliminated it.

Backtested win rate settled on: ~53% EOD exits baseline.

Intraday vs EOD exit test (900 tickers):
  EOD only win rate:      53.0%
  Intraday check win rate: 45.1%  (-7.9 percentage points)
  Conclusion: checking midline intraday HURTS win rate.
  Fix: midline exit only checked at EOD scan (4:15 PM ET).
       Stop loss still checked every 15 min (intraday).

--- PHASE 3: LIVE BOT BUGS FIXED ---

Bot went live ~April 20, 2026. Several bugs discovered and fixed:

BUG 1 -- detect_mode() only running exits 9-10 AM ET
  Problem: exits window was `if 13 <= h < 14` (1 hour only)
  Fix: changed to cover all market hours:
    if (h == 13 and m >= 30) or (14 <= h < 20): return "exits"
  Result: bot now checks exits every 15 min 9:30 AM - 4 PM ET

BUG 2 -- EFX stuck limit sell order
  Problem: cancel_stop_orders() only cancelled STOP type orders,
           not LIMIT type orders. EFX had a limit sell at $178.54
           while price fell to $175.02 -- order never executed.
  Fix: cancel ALL open sell orders regardless of type:
    for o in client.get_orders(req):
        if o.side == OrderSide.SELL:
            client.cancel_order_by_id(str(o.id))

BUG 3 -- do_sell() returning False even when position was sold
  Problem: after limit order filled silently, bot tried to cancel
           already-filled order -> exception -> fell through to
           close_position -> "position not found" -> returned False
           -> transaction not logged
  Fix: after waiting 20 seconds, check if position still exists.
       If "not found" exception, treat as success (already sold).

BUG 4 -- ensure_stop() always failing
  Problem: Alpaca error "fractional orders must be DAY orders"
           GTC stop-limit orders cannot be placed on fractional
           share positions. Was failing silently every run.
  Fix: removed all calls to ensure_stop() completely.
       Software stop-loss check every 15 min is the only mechanism.
       This is fine -- the 15-min check is reliable enough.

BUG 5 -- Intraday midline exits hurting win rate
  Problem: run_exits was checking midline (price > BB midband) every
           15 minutes, causing premature exits on intraday noise.
  Fix: added eod_only parameter to check_exit():
    run_exits calls: check_exit(..., eod_only=False)  <- no midline
    run_scan calls:  check_exit(..., eod_only=True)   <- midline only at EOD

SECTION 3: HOW THE BOT WORKS (technical)
================================================================

--- SCHEDULING ---

GitHub Actions workflow runs every 15 minutes via cron-job.org
hitting the repo's repository_dispatch endpoint.

detect_mode() auto-detects what to do based on UTC time:
  9:30 AM - 4:00 PM ET  -> "exits"  (check stops + max hold)
  4:00 PM - 6:00 PM ET  -> "scan"   (full scan + new entries + daily log)
  Friday after 5 PM ET  -> "weekly" (weekly summary)
  All other times        -> "summary" (status only, no trades)

--- RUN CYCLE ---

exits mode (every 15 min during market hours):
  1. Get all open positions
  2. Fetch current price data
  3. check_exit() for each position:
     - stop_loss: pnl_pct <= -2% -> sell
     - max_hold:  hold >= 5 days -> sell
     - midline:   NOT checked intraday (eod_only=False)
  4. do_sell() for any triggered exits
  5. log_run() writes to runs.csv

scan mode (4:15 PM ET daily):
  1. Fetch SPY for regime detection
  2. Get all positions, enrich with current prices
  3. check_exit() for each position:
     - stop_loss, max_hold, midline (eod_only=True) -- all checked
  4. do_sell() for exits
  5. Scan all S&P 500 stocks for entry signals
  6. Score and filter signals by strategy
  7. buy_position() for qualifying entries if cash available
  8. log_run(), write_daily(), write_dashboard() -> commit to GitHub

--- KEY PARAMETERS ---

EXIT_STOP_LOSS    = -0.02   # -2% stop loss
EXIT_DAYS_MAX     = 5       # 5 day max hold
CASH_RESERVE_PCT  = 0.15    # keep 15% cash aside always
MIN_STOCK_PRICE   = $5.00   # ignore penny stocks
MIN_HISTORY_DAYS  = 220     # need ~1yr of data for indicators

--- SELL LOGIC (do_sell) ---

1. Cancel any existing open sell orders for the ticker
2. Get current position and price
3. Place a limit sell at current_price * 0.998 (0.2% below)
4. Wait 20 seconds, check if filled
5. If not filled: check if position still exists
6. If position gone -> success (filled silently)
7. If position still there -> cancel limit, use close_position()
8. If "position not found" at any point -> treat as success

SECTION 6: KNOWN ISSUES / THINGS TO WATCH
================================================================

1. EFX loss (-9.77% approx, ~$5.87): This was a gap-down that
   bypassed the stop. The position was bought as a GapDown signal
   (intentionally buying after a gap down), then the stock kept
   falling. This is expected risk for that strategy. The bot
   eventually sold it via the 15-min software check once
   detect_mode was fixed. NOT a bug, just bad luck on timing.

2. BIIB potentially unsold: The original do_sell() bug (returning
   False even when sold) may have caused BIIB's sell to go unlogged.
   Check Alpaca account to confirm BIIB position status.

3. Local logs don't sync automatically: The bot runs on GitHub
   Actions, not locally. To get logs locally you must git pull.
   Tyler's Desktop TradingBot folder does NOT automatically get
   new log entries -- it's just a code folder, not a git clone.

4. Windows encoding on Python 3.14: Any script writing files with
   emoji characters will crash on Windows with cp1252 encoding.
   Fix: always use encoding="utf-8" in file write operations.
   This was fixed in strategy_analyzer.py but watch for it in
   any new scripts.

5. Alpaca fractional shares + GTC orders: Cannot place GTC
   stop-limit orders on fractional share positions. Alpaca rejects
   them with "fractional orders must be DAY orders." The bot no
   longer tries to place stop orders -- software check only.
